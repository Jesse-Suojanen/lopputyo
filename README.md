tama projekti on gitin komentorivilla tehty

# lopputyo

Projekti sisältää Gitin jatkotoimintojen harjoitukset.



käytetyt komennot



git clone – repositorion kloonaaminen.



git add – muutosten lisääminen seuraavaan commitiin.



git commit – muutosten tallentaminen versiohistoriaan.



git push ja git pull – muutosten lähettäminen ja hakeminen GitHubista.



git branch ja git switch – haarojen hallinta.



git merge – haarojen yhdistäminen.



git stash ja git stash pop – keskeneräisten muutosten väliaikainen tallentaminen ja palauttaminen.



git revert – aiemman commitin muutosten kumoaminen.



git cherry-pick – yksittäisen commitin poimiminen toisesta haarasta.



git rebase – haaran historian päivittäminen uuden lähtöpisteen päälle.



git tag – version merkitseminen.



git status, git log ja git diff – tilanteen, historian ja muutosten tarkastelu.



git check-ignore – .gitignore-säännön testaaminen.



Mitä opin?

Opin luomaan haaroja yhdistämään muutoksia ja

ratkaisemaan merge-konflikteja.



Miten ratkaisin ongelmat?



Työn aikana tuli vastaan muutamia ongelmia joiden ratkaisemista piti harjoitella. Esimerkiksi merge-konfliktissa samaa tiedostoa oli muokattu kahdessa eri haarassa. Ratkaisin sen tarkistamalla tiedoston sisällön ja valitsemalla mitkä muutokset halusin säilyttää.



Harjoittelin myös keskeneräisten muutosten tallentamista stash-komennolla ja virheellisen commitin peruuttamista revert-komennolla. Jos en ollut varma, missä vaiheessa työ oli käytin git status- ja git log -komentoja tilanteen tarkistamiseen.



Mitä opin työstä?



Opin käyttämään Gitiä paremmin komentoriviltä ja ymmärsin miten haarat ja commitit toimivat käytännössä. Aluksi jotkut komennot tuntuivat hankalilta mutta niiden käyttö alkoi helpottua harjoittelun aikana.



Opin myös, miten merge-konflikteja ratkaistaan ja miten muutoksia voidaan palauttaa tai siirtää haarasta toiseen. Lisäksi opin käyttämään .gitignore-tiedostoa ja luomaan versionumeron tagilla.



Kokonaisuudessaan työ auttoi ymmärtämään, miten Gitillä voidaan pitää projekti järjestyksessä ja miten muutoksia hallitaan turvallisesti.
